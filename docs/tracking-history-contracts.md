# GEO / LEO / SC 有界历史契约

2026-09-22：已实施近期窗口与累计样本分离。此前的读取依赖分析已由代码检查和测试补充：GEO 搜索半径还需要最近十帧失配统计，因此不能只保留四帧。

## 当前窗口

| 策略 | 每目标保留上限 | 必须覆盖的读取 |
|---|---|---|
| GEO | `max(10, numFramesLiving)` | 四帧运动预测、四帧重发现重叠检查、十帧失配搜索半径、可配置连续失配窗口、相邻帧赤经/赤纬重复判断 |
| LEO | 5 | 四帧运动预测和五帧连续失配退出 |
| SC | 4 | 三帧候选及第四帧确认、四帧运动预测；连续跟踪要求最新帧有效 |
| Manual | 2（维持原有上限） | 相邻帧预测；同时接入累计帧数维护 |

GEO 的十帧常量由搜索逻辑与裁剪逻辑共用。`numFramesLiving` 大于十时按配置增大窗口，小于十（包括非正数）时仍保留十帧，保留原有存活规则对该参数的解释。

这些是**每个目标**的历史限制。GEO 输入 FIFO 仍为目标十帧、星点五帧；LEO/SC 输入 FIFO 仍为三帧。

## 累计状态与更新顺序

`TargetInfo` 新增 `discardedFrameCount`，累计样本数通过 `totalFrameCount()` 返回：

```text
总样本数 = 已移除帧数 + frameInfos.size()
```

有效测量与无效占位帧都算样本。累计有效率继续使用原来的初始化值、更新时点与浮点运算顺序，只将分母来源由容器长度改为累计长度。`passesRecentValidityRule` 的预热门槛也使用累计长度。没有把该指标改为近期平均或固定系数的指数平均。

裁剪统一使用 `retainRecentTargetFrames`：保留最新项、累计移除数量，不修改有效率或预测状态。零容量抛出 `std::invalid_argument`，目标不变。前端 erase 使元素引用和迭代器失效。函数不逐帧 shrink_to_fit，避免重复分配；生产轨迹从短候选开始，因此 vector 容量受窗口约束，不随轨迹时长增长。一次更新可暂时多出一帧，返回前已裁剪。

- GEO 完成本帧跟踪、存活判定和重发现后，裁剪所有返回目标。
- LEO/SC 完成连续跟踪更新和存活判定后裁剪；三帧初始候选与第四帧确认保持完整。
- 原有候选、已确认状态继续由各策略保存，没有新增重复的状态机或另存一份初始历史。
- 初始候选去重拒绝已裁剪目标，防止把近期后缀误当初始帧；在线目标重叠仍通过最近帧接口判断。
- `reset`、目标清空和重新发现创建的新目标会清零移除计数；普通复制携带累计状态。

**不能直接 erase 而不更新计数。**例如更新前有效率 0.75，第 100 帧失配时，完整历史结果为 0.7425；丢弃前 96 帧而未保存累计数会得到 0.5625。既有反例测试保留，新对照测试证明通过裁剪接口后有效率与完整历史一致。

## API 与消费者

`frameInfos` 现在明确表示近期窗口，完整长度应使用 `totalFrameCount()`。这是返回历史内容的契约调整；新增成员也改变了 `TargetInfo` 的 C++ 布局，依赖此类型的二进制消费者需要重新编译。未修改网络和存储报文格式。

已检查仓库内消费者：`makeResultPacket(s)` 读取最新帧，存储和通信通过该转换使用结果；跟踪 UI 使用数量、目标 ID 和预测值，不依赖完整历史。`TrackResultEvent` 的 Doxygen 同步为近期快照。需要完整轨迹的消费者应逐帧保存结果，不应从一次事件取回全部历史。

2026-09-23 生命周期补充：GEO 在失活当帧返回一次最终快照，下次 `track` 入口移除；仍活跃目标保持 ID，重发现使用新 ID，`reset` 后编号重新开始。停止调用后最多保留最后一帧的终态集合，直到下一次调用、reset 或销毁；不建立另一份全历史归档。

`ImageProcessor` 每次实际执行跟踪策略都发布结果，包括空列表。UI 仅统计和显示 `living` 目标，没有活跃目标时清空。网络转换仍读取最新测量的 `valid`，有效的最终测量正常发送一次；空列表不生成 GXTC/GDCL 数据报。轨迹存储仅追加有效测量，空列表或无效测量不写行。`living=false` 与 `valid=false` 不是同一语义，不能用前者过滤最后一次有效测量。

这消除了失活目标在持续跟踪其他目标期间反复返回造成的旧帧重复发送/写入；不新增可靠传输重试、持久化终态标记或跨会话全局唯一 ID。活跃目标数量、候选密度和容器容量峰值仍需单独预算，不宣称整个目标集合具有固定数量上限。

## 回归约束

- 三种跟踪器各运行 1000 帧；GEO 覆盖非正数、4、17 三组存活窗口，并与未裁剪历史逐帧对照预测、十帧失配数量及结果包关键字段。
- LEO 长轨迹包含周期性失配，检查第五次连续失配退出与 reset 后累计数；SC 检查长轨迹、立即失配退出和自然重发现。
- 生命周期辅助函数对 4、5、17 帧窗口各对照 3000 帧，包含孤立失配、长失配段、恢复及大于保留容量的年龄门槛。
- 四帧预测对照 3000 帧，包含有效/无效切换、运动扰动与变化帧率，比较累计有效率、像面/AE 位置与速度。
- 初始候选去重与近期重叠采用不同测试，防止索引语义混淆。
- 原有失配恢复、GEO RA/Dec、候选确认、重复测量、结果转换和 legacy scenario 测试继续保留。
- 1,200 帧中保留一个持续目标并反复发现/丢失 100 个短轨迹，混合有效测量导致退休与连续失配，检查每个最终快照仅出现一次、最新帧序号和活跃 ID 稳定，全部退出后返回空列表。
- 独立检查最终有效测量仍可存储和发送、空事件不重复写入/发送，UI 忽略失活快照并能清空。
