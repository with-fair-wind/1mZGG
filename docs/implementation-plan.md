# 后续实施计划

更新：2026-09-28。本文只维护尚未完成的工作、依赖和验收条件。当前架构见 [总览](overview.md)，已运行测试及未覆盖范围见 [验证矩阵](validation-matrix.md)，性能证据见 [资源验证](resource-validation.md)。

## 1. 持续验证与生命周期覆盖

- 发布 `.github/workflows/sanitizers.yml` 后，取得 Windows core/Qt ASan 与 Linux core TSan 的真实 runner 结果，保留各项 JUnit 和失败日志。有效的 GitHub 登录是查询、手动触发工作流的前提；本机通过或 YAML 解析不能替代远端验收。
- 现有核心和 Qt ASan 已覆盖处理器、回放及部分 ViewModel；组合根持有外部服务引用时的关闭回归仍需加入 sanitizer 覆盖评估，不能把部分 Qt 套件描述成全应用内存审计。
- 审查 UI 中无 context 的 lambda 连接，重点是回放进度、显示拉伸和统计控件；确认发送方与控件销毁顺序后补 context，并验证窗口关闭后无回调访问。旧清单的固定数量及旧行号不再作为依据。
- 后续扩展实时采集/回放切换时，统一会话 ID、取消及停止顺序；已进入的解码或用户回调无法强制中断，最终关闭仍需等待返回。

验收：真实 runner 成功；失败不得以跳过替代通过。生命周期变更须有确定性交错测试，关闭后拒绝新任务，已取消或旧会话的完成回调不能恢复服务或 UI 状态。

## 2. 存储持续吞吐与过载策略

- 使用 `dss_tracking_io_baseline` 的输入周期参数，测量 100/250/500/1,000 帧/s 及无节流负载，再对临界负载延长至至少 10 分钟；保持目标数、输出盘和工具链可比。
- 增加持续 RAW、大图、磁盘满/写入失败和跨机网络场景，记录队列峰值、接受/拒绝、服务耗时、工作集与停止时间。现有约 20 秒、仅前 64 帧写 RAW 的结果不能替代持续采集验收。
- 先测量轨迹 writer 的格式化、文件打开/刷新和锁持有成本，再决定是否采用保持文本格式的有限批量写入。另测 ImageSender 延迟生成对完整处理线程每帧耗时的影响。
- 无损回放若采用可取消背压，必须验证停止/失败唤醒、会话切换与顺序；实时采集另行确定超载反馈和允许丢弃政策。不得以无限队列或单纯增大预算掩盖瓶颈。

验收：已接受请求数等于完成数，归档行数与内容可复核，拒绝均有记录，资源和停止行为遵守预算。改前/改后使用同一负载；生产帧率、延迟与无损要求需由实际设备和业务约束确定。

## 3. 协议与真实设备闭环

| 待办 | 前置与验收条件 |
|---|---|
| GXTC/GDCL 时间字段 | `makeJms1970Centiseconds` 仍将全纪元厘秒转换为 int32；取得权威 4 字节字段语义和现代日期黄金报文后决定编码与范围校验，不能擅改为日内时间或改变报文宽度。 |
| 串口角度与转义 | 确认帧体转义及 360° 的合法编码；`decodeAngle` 不能简单加 29 位掩码，否则可能把合法 360° 变为 0°。定义畸形输入的拒绝和诊断规则。 |
| 串口发送与重连 | 明确缓冲写入、设备接收和业务应答的区别，定义超时、部分写入失败、可取消退避及重复命令语义；防止有副作用命令重复执行。 |
| 相机与 Sapera | 将实际 `ICameraSerialPort` 注入控制器，通过配置选择硬件；按 [硬件验证](hardware-validation.md) 测试长采集、字节流异常、拔插、停止、重启及关闭期间回调。 |
| 气象来源与范围 | 取得设备帧头、物理范围和部署信任边界，补充错误统计/来源校验要求；现有 NaN/Inf 拒绝不等于鉴权。 |

验收：协议样本及设备命令/应答日志可复查，模拟端与实际设备均通过，连接和失败状态可在 UI 观察；设备到位前不标记完成。

## 4. 科学计算与跟踪黄金数据

- 明确暗场/平场、光度、星图匹配、天球坐标、指向误差、TWDW 的输入输出、单位、有效性和容差；用显式状态表达未计算，避免零值混同缺失值。
- 统一 `MeasuredBlob::ra/dec` 从上游写入、预测到 GEO RaDec 跟踪的单位。当前跟踪边界/阈值采用弧度，字段注释与部分预测样本仍需对齐，先确认上游契约再改。
- 复核 `samplePeriodError` 的周期误差包裹、负分支可达性和 `minimumSamplePeriod` 的误差门槛，补正负样本、跨周期及异常输入参考结果。
- 补 GEO 逆向运动与星速方向差的专项测试、超过 2,000 blob 的准入测试和实际候选密度基准；空间索引优化须保持候选关联结果。
- `isSameEquatorialPoint` 已分别处理赤经/赤纬阈值，并拒绝缺少 alpha/sigma 的比较；继续确认 ra/dec-only 的业务语义，补高赤纬和缺失坐标样本，不复用旧清单中已过期的修复方案。
- 明确非有限质心、`median3`、`targetFrameMotionAt` 索引前置条件与不可编码串口字段的处理；增加防御检查前先确认调用契约，不以返回零掩盖错误。
- 用同一黄金数据核对显示、轨迹存储和网络结果，覆盖无目标、南天、时间戳、模式切换及失败/重发现。若要求目标总量硬预算或持久化终态标记，先定义准入与归档格式；现有每目标历史窗口不保证目标总数有界。

验收：各算法有独立参考结果、误差阈值和回归测试；合成序列与历史窗口测试不能替代真实科学精度验收。

## 5. CUDA、界面与测量驱动的收敛

- 在目标 GPU 上执行 6144 级 CPU/CUDA 输出对照、数值容差、显存预算和错误回退验证；测量传输、分配及回读在内的完整收益。满足 [硬件验证](hardware-validation.md) 门槛后才向 UI 开放 CUDA 选择，并补距离曲线与联调状态。
- 按热点证据评估处理缓冲复用、UDP 接收拷贝、GPU 非连续 stride 上传、现代 OpenGL/兼容上下文和高频日志容器；每项分别验证生命周期及跨驱动兼容性。
- 测量后再决定存储头文件拆分和模板显式实例化；曝光时间单位统一需兼容协议、配置与 UI。ServiceRegistry 窄接口注入、Config 单例及 TrackManager 收敛随实际消费者推进，不先增加通用框架。

验收：优化有相同条件下的正确性和性能对照，CPU 回退保留，后端选择不改变输出契约和关闭行为。
